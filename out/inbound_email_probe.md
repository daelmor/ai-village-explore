## Schema facts

Fields of a `computer_use_turns` row (per data/SCHEMA.md and verified on sample rows): `id, session_id, agent_action, agent_messages, output, error, system, screenshot_is_redacted, has_redaction_been_overruled, created_at, updated_at`. `agent_messages` holds the raw provider response (narration text, thinking/reasoning, tool-call arguments); `agent_action` is the executed action (click coordinates, typed `text`, bash `command`); `output`/`error`/`system` are tool stdout/stderr/notes. `base64_image` and `redaction_reason` are not exported. Turn joins to agent via `session_id` -> `computer_use_sessions.agent_id` -> `agents.id`.

**Is there any OCR / accessibility-tree / text-of-screenshot field? NO.** The only screenshot content is in image tars (not examined here). Text that appears from the screen exists only if the model itself transcribed it in narration/thinking/actions, or if a bash/tool `output` happened to carry it.

## Classification regexes (applied to the concatenation of agent_action text, agent_messages text, output, error, system for each turn; first matching class wins, A > B > C > D)

Signals (case-insensitive): `From:` = `\bfrom:`; `Subject:` = `\bsubject:`; `inbox` = `\binbox\b`; `unread` = `\bunread\b`; `received an email` = `received an? e-?mail`; `replied` = `\breplied\b`; `wrote:` = `\bwrote:`; `@gmail.com` = `@gmail\.com`; `re:` = `\bre:`; `Guido` = `guido`; `crthpl` = `crthpl`; `Bayesian` = `bayesian`

- **A (full body)**: in `output`/`error`, the Gmail-CLI read format `From:[^\n]*\n\s*To:[^\n]*\n\s*Subject:[^\n]*\n\s*Date:[^\n]*\n\s*-{20,}\n(?P<body>.{40,})` (headers, dashed rule, then body), and the From: line is not the agent's own address (own sent copies excluded).
- **B (sender + subject only)**: Gmail-CLI list format `ID:\s*[0-9a-f]{12,}\s*\n?\s*From:[^\n]*\n\s*Subject:[^\n]*` (sender, subject, date, 1-line preview in `output`); or an agent transcribing an inbox row `"[^"\n]{2,40}"\s*-\s*"[^"\n]{3,80}"` (with an email word in the turn); or prose `(email|message|mail)s?\s+(from\s+\S+.{0,120}?)?(with\s+)?(the\s+)?subject\s*[\"'“‘:]`; all searched only in agent_messages text and output/error (not in typed/bash-command text).
- **C (paraphrase)**: `(e-?mail|message)s?\b.{0,160}\b(from|said|says|asked|asking|saying|told|suggest\w*|replied|reply|wrote|sent|advis\w*|request\w*)\b|\b(replied|wrote|responded)\b|\b(received|got)\b.{0,40}\be-?mail` together with `e-?mail|gmail|inbox|unread` (non-action text); or Guido/crthpl/'received an email'/'wrote:' together with an email word.
- **D**: some signal matched (e.g. 'inbox', 'unread', 're:', '@gmail.com') but none of the above.
- Caveats: regex heuristics; first matching class wins (A>B>C>D). C over-counts (agents discussing emails they send, or the word 'message'); D is mostly the word 'inbox'/'re:'/'Bayesian' in unrelated text. Treat counts as rough, and the examples as the evidence.

## Verdict

**Partially.** Emails are not recoverable from any text/OCR log for the agents that read mail through the Gmail web UI (the Claude models, including Opus 4.5 with Guido and Opus 4.6 with crthpl). The dataset has no OCR/accessibility/screenshot-text field, so the only surviving content is what the model chose to say about the screen: a transcribed inbox row (sender name, truncated subject, time), sometimes a short quote ("Stop."), and its own paraphrase or bullet list of the body (class B/C; never a verbatim full body, and the Guido and crthpl bodies cannot be checked against the original). The "signed-by gmail.com" check and the full 2:58 PM text exist only in screenshots. Agents that use a Gmail command-line tool through bash (DeepSeek, GLM, some others) leak full inbound emails (headers + body) or sender/subject/preview lists into the tool `output` field (classes A/B above), so for those agents inbound mail is recoverable verbatim.
**What would be needed:** (1) the screenshots (image tars `images/computer-use-turns/<PT date>.tar`, keyed by turn id) plus OCR/vision transcription for the GUI agents; or (2) server-side logging of the mailbox (the quarantine/Gmail API message store) joined to agent addresses by timestamp; or (3) scaffolding that logs an accessibility tree / page text per turn.
