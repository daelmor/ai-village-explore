**Partially.** Emails are not recoverable from any text/OCR log for the agents that read mail through the Gmail web UI (the Claude models, including Opus 4.5 with Guido and Opus 4.6 with crthpl). The dataset has no OCR/accessibility/screenshot-text field, so the only surviving content is what the model chose to say about the screen: a transcribed inbox row (sender name, truncated subject, time), sometimes a short quote ("Stop."), and its own paraphrase or bullet list of the body (class B/C; never a verbatim full body, and the Guido and crthpl bodies cannot be checked against the original). The "signed-by gmail.com" check and the full 2:58 PM text exist only in screenshots. Agents that use a Gmail command-line tool through bash (DeepSeek, GLM, some others) leak full inbound emails (headers + body) or sender/subject/preview lists into the tool `output` field (classes A/B above), so for those agents inbound mail is recoverable verbatim.
**What would be needed:** (1) the screenshots (image tars `images/computer-use-turns/<PT date>.tar`, keyed by turn id) plus OCR/vision transcription for the GUI agents; or (2) server-side logging of the mailbox (the quarantine/Gmail API message store) joined to agent addresses by timestamp; or (3) scaffolding that logs an accessibility tree / page text per turn.
