## Heuristic limits

- **Directive detection** is regex-based (imperative verbs at line start, cues like *please*, *assignment*, *STOP*, @-mentions). Long status updates that embed a request are counted as directives; terse implicit requests may be missed. Code/file dumps and messages addressed only to admin are excluded (e.g. the Episode B tool-loop messages 242496–242514).
- **Addressees**: @-mentions win; otherwise agent names appearing in directive-bearing lines; else `all`. Bare short names ("Gemini", "Kimi", "Claude" after 2026-06-01) are aliased per episode.
- **Response class** is inferred from the follower's own chat text only: a follower message counts as relevant if it mentions the leader or shares ≥2 content words with the follower's part of the directive; the headline class per pair is ranked refused > counter_proposal > complied > questioned > acknowledged_only (all classes seen are kept in `notes` as `classes_seen`). Refusal cues must be explicit ("I won't do", "I disagree with the plan"); counter-proposals need "I'd suggest"/"instead we"/"already exists"; questions need a '?' sentence that names the leader or uses "could you/should I/which". `complied` means the follower *claimed* to start/finish the work ("done", "pushed", "PR #", "I'll take"), not that the work was verified, and not that it was *caused* by the directive. Some `complied` labels are inferred from topical overlap alone (flagged in `notes`).
- `ignored` covers both no message in the 90-min window and messages that never touch the directive (`notes` distinguishes `no_message_in_window` vs `spoke_in_window_but_unrelated`).
- **Text-coded `complied` is close to its base rate**: the placebo rows above show nearly the same share of "complied" in the 90 min *before* each directive, because followers continuously post first-person work reports. Treat `complied` as "the follower posted relevant work", and prefer the before/after contrast and `followed_action_evidence` (Episode B: clear lift; Episode A: none) as evidence of influence. Leaders also often ratify work already in progress (e.g. B 243870, 243894 announce results of follower work), which inflates apparent compliance.
- Overlapping windows: one follower message can be the response to several directives posted close together (e.g. 155994 answers 155680, 155888, 155924, 155983, 155993), so pair counts are not independent. Some headline classes are wrong on inspection (e.g. 153622 GPT-5.1 *supports* the leader but is coded counter_proposal).
- `followed_action_evidence` uses bag-of-words overlap ≥2 (stopwords + agent-name tokens removed); project jargon shared by everyone (e.g. *archive*, *tests*, *report*) inflates it. Episode A agents log START_USING_COMPUTER.sessionGoal; Episode B agents mostly log CONSOLIDATE.nextSessionGoal.
- Vote-out / reflection flags are keyword-based; they include benign uses (e.g. Episode B "KEEP-vote" on which checkpoint becomes leader). Read `out/leader_reflections.csv` before quoting.
